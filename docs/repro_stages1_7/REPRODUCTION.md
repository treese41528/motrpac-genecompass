# Reproducing Stages 1–7 (the v2 model build): status 2026-10-31

**Question.** Can the v2 model's inputs (corpus, gene universe, tokens, medians, priors, init, training mix)
and the start of its training be rebuilt from the repository and the files on disk, and do they match what v2
was trained on?

Every rerun writes to scratch (`/scratch/gilbreth/reese18/motrpac_repro_20261031/`, through scratch-only
profiles); no repository data, config or canonical output was touched. Files in this folder:
`stage2_step1_gene_universe_diff.tsv` (genes in only one of the two universes) and
`stage2_reference_file_mtimes.txt` (dates of the Stage 2 symbol/synonym reference files).

## Result so far

**Stage 2, step 1 (gene universe) does not reproduce.** Same config, same 20,942 input matrices, same
`rat_gene_info.tsv` md5 as the canonical run of 2026-02-22 (git 14ab1ba). The rerun resolves 3,968 fewer raw
gene IDs by RGD synonym (4,131,376 vs 4,135,344), and its universe has 22,485 genes against 22,488 (28 only in
the rerun, 31 only in the canonical file).
- Likely cause: the symbol and synonym references (`GENES_RAT.txt`, `*_gene_synonyms.tsv`,
  `*_symbol_lookup.pickle`) all carry a 2026-02-24 date, two days after step 1 ran. Step 1's manifest records
  only the md5 of `rat_gene_info.tsv`, so the synonym files it actually read cannot be checked. (That file
  also carries the 02-24 date with an unchanged md5, so the dates show the folder was rewritten, not
  necessarily that every file changed.)
- Effect on v2: none directly. Stages 3–5 read the canonical `pruned_gene_universe.tsv` (22,213 genes), which
  is kept. The finding is that this file cannot be rebuilt byte for byte from the current reference files.

**Found by reading the code** (to be confirmed by the pending jobs where marked):
- `rat_model_init.py` drew its random rows (T3 noise, T4 word rows, the rat species CLS row) with no seed, so
  the v2 init cannot be regenerated byte for byte. **Fixed for future builds:** `--seed` (2026-10-31). The
  pending job builds the init twice to measure the difference.
- `pipeline/run_stage6.py` named Step 4 `build_grn_embedding.py`; the script is `build_grn_transfer.py`, so
  the orchestrator could not run Step 4. **Fixed** (2026-10-31).
- The on-disk Stage 6 family priors were built from an older Stage 3 `rat_token_mapping.tsv` (md5 26a810ed
  against the current 258ffccb; Stage 3 was rerun 2026-04-01). This reaches v2 only through its 36 T4 GRN
  rows; v2's init takes no family, promoter or co-expression rows for T4 from Stage 6.
- Stage 6 promoter fetches TSS coordinates from live BioMart (the current release) unless a cache exists, and
  co-expression takes about 49 h and refuses the default config. Neither enters v2; neither is rerun.
- The task counts behind Stage 4 (16) and Stage 5 (50) are recorded only in the manifests and in gitignored
  SLURM scripts, and Stage 5's row order depends on them.
