# Reproducing Stages 1–7 (the v2 model build): 2026-10-31 to 11-01

**Question.** Can the v2 model's inputs (corpus, gene universe, tokens, medians, priors, init, training mix)
and the start of its training be rebuilt from the repository and the files on disk, and do they match what v2
was trained on?

Every rerun writes to scratch (`/scratch/gilbreth/reese18/motrpac_repro_20261031/`, through scratch-only
profiles); no repository data, config or canonical output was touched. Comparison tables (`stage*.tsv`, one row
per compared file or tensor), timings and the scripts/SLURM files/profiles used (`scripts/`) are in this folder.
The scratch outputs were deleted after comparison.

## Stage 2 step 1 and code review (first results)

**Stage 2, step 1 (gene universe) does not reproduce.** Same config, same 20,942 input matrices, same
`rat_gene_info.tsv` md5 as the canonical run of 2026-02-22 (git 14ab1ba). The rerun resolves 3,968 fewer raw
gene IDs by RGD synonym (4,131,376 vs 4,135,344), and its universe has 22,485 genes against 22,488 (28 only in
the rerun, 31 only in the canonical file).
- Likely cause: the symbol and synonym references (`GENES_RAT.txt`, `*_gene_synonyms.tsv`,
  `*_symbol_lookup.pickle`) all carry a 2026-02-24 date, two days after step 1 ran. Step 1's manifest records
  only the md5 of `rat_gene_info.tsv`, so the synonym files it actually read cannot be checked. (That file
  also carries the 02-24 date with an unchanged md5, so the dates show the folder was rewritten, not
  necessarily that every file changed.)
- Effect on v2: none directly. Stages 3–5 read the canonical `pruned_gene_universe.tsv` (22,213 genes), which
  is kept. The finding is that this file cannot be rebuilt byte for byte from the current reference files.

**Found by reading the code** (to be confirmed by the pending jobs where marked):
- `rat_model_init.py` drew its random rows (T3 noise, T4 word rows, the rat species CLS row) with no seed, so
  the v2 init cannot be regenerated byte for byte. **Fixed for future builds:** `--seed` (2026-10-31). The
  pending job builds the init twice to measure the difference.
- `pipeline/run_stage6.py` named Step 4 `build_grn_embedding.py`; the script is `build_grn_transfer.py`, so
  the orchestrator could not run Step 4. **Fixed** (2026-10-31).
- The on-disk Stage 6 family priors were built from an older Stage 3 `rat_token_mapping.tsv` (md5 26a810ed
  against the current 258ffccb; Stage 3 was rerun 2026-04-01). This reaches v2 only through its 36 T4 GRN
  rows; v2's init takes no family, promoter or co-expression rows for T4 from Stage 6.
- Stage 6 promoter fetches TSS coordinates from live BioMart (the current release) unless a cache exists, and
  co-expression takes about 49 h and refuses the default config. Neither enters v2; neither is rerun.
- The task counts behind Stage 4 (16) and Stage 5 (50) are recorded only in the manifests and in gitignored
  SLURM scripts, and Stage 5's row order depends on them.

## Stage 7 training restart: result (job 12103825, 31 min, 2026-11-01 14:23–14:54, 4 × A100-40GB)

Phase 1 restarted from the canonical `rat_genecompass_init_v2` on the canonical `mixed_species_dataset_v2`, with the
committed `rat_finetune_v2.yaml`, default seeds (seed_num 0, seed_val 42, Trainer seed 42) and the same launch as
`slurm/finetune/stage7.slurm` (torchrun, 4 GPUs, fp16, gradient checkpointing). Output to scratch. Stopped after step
2,000 (2,003 per-step entries). Compared with the `log_history` in v2's `checkpoint-480000/trainer_state.json`
(`stage7_train_loss.tsv`).

**Result: the trajectory reproduces, within GPU floating-point nondeterminism.**
- Learning rate identical at all 40 logged points.
- 50-step mean training loss (`loss`, 4 decimals as logged): equal at 39 of 40 points, the other off by 0.0001
  (step 2,000: 0.7164 vs 0.7165). For example: step 50, 1.0092 / 1.0092; step 500, 0.8120 / 0.8120; step 1,000,
  0.7454 / 0.7454.
- Per-step rank-0 gene-ID loss: steps 0 and 1 are bit-identical. From step 2 on, the values differ by a median of
  6e-5 and at most 9.2e-4. Value loss differs by at most 1.3e-4. The gap does not grow over the 2,000 steps
  (per-500-step median 5e-5 to 7e-5), so the batches and masks are the same and only fp16/cuBLAS reduction order
  differs.
- `torchrun exit 1` in the job log is from the planned SIGTERM after step 2,000, not a failure.

Not covered: the remaining 515,793 steps of phase 1 and all of phase 2. With nondeterministic GPU kernels, a full
rerun would not be bit-identical; the C1/C2 probe scores are the right check on a rebuilt model.

## Follow-up (2026-11-01): Stage 2 diagnosis, the 27 raw-slot files, and the fixes

**Step 1: the reference files changed; the code did not.** Job 12118753 ran step 1 twice on the current inputs:
once with the February code (a worktree at 14ab1ba) and once with HEAD. The two runs gave the same result:
`gene_universe.tsv` md5 02991870 both times, 22,485 genes, against the canonical fe62f634 (22,488 genes).
Compared with the canonical `gene_resolution.tsv`, 214 of 568,594 raw IDs resolve differently, and every one is
an RGD-synonym change: 106 resolved by synonym in February and unresolved now, 96 the reverse, 10 resolved by
synonym to a different gene, and 2 empty/unresolved swaps. So the synonym references in `data/references/biomart`,
rewritten on 2026-02-24, are the cause. They cannot be restored from upstream because the files step 1 read were
overwritten. What was done:
- `config/reference_md5sums.tsv` now records the md5 of every reference file, and step 1 refuses to run when one
  differs (override: `--allow-reference-drift`).
- The current reference files are on the deposit list, so a rebuild can use exactly the files that
  `config/reference_md5sums.tsv` pins.

**The 27 raw-slot files are reproducible.** The canonical run produced none of them because the six studies'
`_RAW` folders were empty after the 2026-02-21 RAID recovery. The 27 files in the corpus came from the cancelled
2026-02-18 run. Job 12118868 unpacked the series archives, including the nested per-sample `GSM*.tar.gz`, and
ran the committed Stage 2 on the six studies:
- GSE127248's series `RAW.tar` on GEO is truncated (6,066,176 bytes) and the URL now returns 404, so its 24
  files were downloaded per sample.
- **All 27 regenerated files match their canonical counterparts:** same barcodes and identical counts on every
  shared gene (maximum absolute difference 0; `rawslot_cmp` table below).
- One difference: the 8 GSE253767 files have 17,351 genes against the canonical 17,352. The canonical gene
  universe was used, so this predates the reference change: the cancelled 02-18 run's gene set.

The steps are now committed:
- `scripts/restore_rawslot_studies.sh` unpacks the six studies, checking every archive and file against
  `config/rawslot_restore_md5.tsv` and downloading GSE127248 per sample. It was tested end to end in a fresh
  folder (job 12120952).
- `config/stage2_sample_order.tsv` pins the 27 canonical IDs to their source files. On the restored tree all 27
  get the right file under both forward and reversed discovery order. Under the walk-order numbering they had
  come out as other IDs (for example, canonical `GSE127248_sample0` was regenerated as `sample7`).
- The regenerated files hold counts in X, while the canonical files held log-normalized X with counts in `.raw`.
  Their md5s therefore differ from `config/corpus_v2_plan.tsv`; `raw_counts_adata` reads counts from either.

**Stage 2 numbering now depends only on the table, not on the filesystem.** `<study>_sample<idx>` was the
file's position in `os.walk` order. That order is filesystem-specific: sorting instead would renumber 371 of 529
studies. `config/stage2_sample_order.tsv` (1,038 canonical rows plus the 27 above) fixes every ID. Tested on the
real tree, 1,038/1,038 IDs come out right in native order and 1,037 with every listing reversed. The exception
is `GSE128992_sample0`, a multi-species folder that failed to load in both runs.

**IHW was already seeded.** An audit claim that the Stage 10 DE used unseeded IHW folds was wrong: `ihw()`
defaults to `seed = 1L` and calls `set.seed` itself (checked in R, IHW 1.34.0). The DE results were reproducible.
`run_pseudobulk_de.R` now passes `DE_SEED` (config `deconvolution.de_seed: 1`) explicitly. Because that is the
same value, no numbers change.

**What still cannot be regenerated, so it must be deposited:**
- **The v2 QC h5ads.** These are needed for a byte-exact rebuild; the 187 files above differ through the old
  synonym files.
- **The reference files** in `data/references/biomart` and the HGNC copy.
- **The v2 init**, unseeded at the time.
- **Inputs from external or one-off processes:** the LLM study classification, the consensus cell annotations,
  the joint labels, and the author label objects for BAT and HEART.

The final weights are the latest checkpoint: `models/pytorch_model.bin` md5 ae6100ff equals `checkpoint-591763`.
