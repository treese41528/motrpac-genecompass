# Deconvolution rebuild runbook — config-driven, validated, from start (2026-07-15)

The Stage-8 deconvolution reference layer was **rebuilt from scratch** to the reference decisions in
`REFERENCE_SELECTION_PLAN.md` (Geyu's note), with a hard guard that every reference is built from — and validated
against — an exact, locked sample selection *before* any bulk is deconvolved. This document is the reproducible
runbook + the verification record. It exists because the old build path let a ~85%-non-rat cortex reference and
a rat-mouse-chimera muscle reference reach production; that class of bug is now structurally impossible.

## 0. Reproduce the 16-tissue default from a clone (2026-11-01)

The default config (`config/pipeline_config.yaml`) is refs4 on all 16 tissues with the v2 model: KIDNEY, LIVER,
BLOOD, CORTEX, HEART, WATSC, SKMGN, SKMVL, BAT, HYPOTH, SMLINT, LUNG, HIPPOC, TESTES, SPLEEN, OVARY
(`REFERENCE_RELABEL_PREREG.md` §14/§16; results in `ALL_TISSUE_RERUN_RESULTS.md`, c3b27c7). Outputs:
`results_refs4all/`, `genecompass_input_v2_refs4all/` (+ `_human/`), `augur_input_v2_refs4all/`,
`grn_v2_refs4all/` (+ `_human/`). ADRNL, COLON and VENACV have no reference.

**How the current tree was made vs. the clean path.** The tree on disk was ASSEMBLED: 14 tissues were linked in
from earlier arms (BAT/HEART/HYPOTH/TESTES from July, the rest from refs4), SPLEEN/OVARY were run in place, and
only the cross-tissue steps were rerun over all 16. `deconvolution/assemble_arm.py` is the committed record of
those links (`python deconvolution/assemble_arm.py refs4all` prints them). The commands below are the CLEAN path:
every tissue is built straight into the config's folders from `tissue_references.yaml`, with no links and no
hand-edited paths. To compare a clean rebuild against the assembled tree, run everything below with
`export PIPELINE_PROFILE=config/profiles/refs4all_rebuild.yaml` (fresh `_refs4all_rebuild` folders and a fresh
validation folder); without it, `run_deconv_all.py` refuses to write into the linked default tree.

Inputs marked **[deposited]** are not regenerated by these commands; they must be present (from the authors'
deposit or the upstream stages) for an exact reproduction.

### 0.3 ID-space audit and bulk liftover (compute node; minutes)


`prepare_motrpac_bulk.R` reads the audit's corpus gene sets (for `motrpac_missed_genes.tsv`), so run the audit
first. An `ALL` run REWRITES the committed `motrpac_bulk_liftover.tsv`, `motrpac_bulk_liftover_report.txt` and
`motrpac_missed_genes{.tsv,_summary.txt}` (single-tissue runs, i.e. Stage 8 step 1, never do); the `git diff`
check proves the liftover reproduced. The TESTES, SPLEEN and BLOOD references are lifted with this map, so it
must come before 0.5.

### 0.4 Joint re-annotation (optional: the deposited `cells_final.tsv.gz` are used otherwise)

```bash
for REF in KIDNEY LIVER CORTEX WATSC MUSCLE SMLINT LUNG HIPPOC BLOOD_PBMC BLOOD_WB BLOOD_BM SPLEEN OVARY; do
  python deconvolution/joint_reannotate.py run --ref $REF        # compute node (HIPPOC: 279k cells)
  python deconvolution/joint_reannotate.py finalize --ref $REF   # applies joint_reannotation_review.tsv
done
python deconvolution/build_blood_composite.py checks             # BLOOD option B §12 checks
```

The review decisions (`joint_reannotation_review.tsv`, `joint_reannotation_splits.tsv`) are keyed to Leiden
cluster IDs. `deconvolution/joint_reannotation_clusters.tsv` records a SHA-256 of the cluster assignment each
reference's decisions were made on; `run` reports whether it reproduced it and `finalize` REFUSES a different
assignment (renumbered or re-partitioned clusters would put the decisions on the wrong cells). If that happens,
use the deposited `cells_final.tsv.gz` (skip this step), or re-review and record the new assignment with
`finalize --ref <REF> --record-clusters`.

### 0.6 Stages 8 + 9, per tissue (GPU jobs)

```bash
python pipeline/run_deconv_all.py --validate-only                # both gates, all 16
python pipeline/run_deconv_all.py --submit --from-step 2         # one sbatch per tissue (bulk prepared in 0.3)
```

Each job runs BayesPrism (`run_stage8.py`: deconvolve, extract Z, build pseudo-cells) then `run_stage9.py`

## 3. `tissue_references.yaml` v3 — per-tissue keys

`status` (ready | needs-build | needs-online-data | proposed | blocked) · `reference_dir` · `study` · `tissue`
(tissue_normalized, exact) · `organism` (default `Rattus norvegicus`) · `conditions` · `title_include` /
`title_exclude` (geo_title regex) · `sample_ids` · `dedup_gsm` · `label_scheme` · `gene_join` · `allow_nonnative`
(bypass reference_qc when a sort is intrinsic, e.g. SPLEEN) · `expect:` {`n_samples`, `sample_ids` (post-QC,
exact), `qc_dropped` (intended drops), `organism`} · `build` (reproducible command).

Note: a geo_title regex that starts with `-` (e.g. Ma's `-Y` arm) must be written `[-]Y($|\b|_)` — a leading dash
is otherwise mistaken for a CLI flag by argparse. The build driver also passes title filters as `--opt=value`.

## 4. What the guard guarantees (run BEFORE deconvolving)

For every buildable tissue, `validate_selection.py` asserts (FAIL = refuse to deconvolve):
1. **Exact selection** — resolved `select_samples()` == `expect.sample_ids` (and `n_samples`).
2. **QC drops only the intended** — the reference_qc gate removes exactly `expect.qc_dropped` (catches both a
   wrong-thing drop and a missed drop). E.g. LIVER drops exactly its 2 Visium spots.
3. **Organism** — every selected sample is `Rattus norvegicus`.
4. **Inputs present** — h5ad + celltypes + consensus annotation exist (else the build silently drops the sample).
5. **Built artifact** — if built, `cells_meta.tsv` used exactly `expect.sample_ids`.
Negative-tested: it FAILs on wrong sample_ids, a disabled organism gate, and a wrong qc_dropped expectation.
